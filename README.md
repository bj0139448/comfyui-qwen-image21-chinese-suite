# ComfyUI-ChineseImageSuite —— 中文生图套件

面向中文用户的 ComfyUI 生图节点族：多视图提示词组装、换装提示词组装、多视图分割线后处理、不掉画质加速开关。
**零第三方依赖**（只用 ComfyUI 自带 API 与标准库），MIT 许可证，可直接提交到 ComfyUI 节点库。

## 节点清单

| 内部名 | 显示名 | 作用 |
|---|---|---|
| `ChineseT2IPanel` | 纯文生图面板·ChineseImageSuite | 提示词+人物/场景预设+分辨率档+速度档 → 提示词/宽/高/步数/加速强度 |
| `ChineseMultiView` | 多视图提示词组装·ChineseImageSuite | 人物提示词 + 视图模式 → 完整提示词 + 格数 |
| `ChineseOutfitSwap` | 换装提示词组装·不换脸 | 输入类型 + 服装描述 → 换装提示词 + 建议 denoise |
| `GridLineDraw` | 多视图分割线 | 按格数在成图上画等宽竖直分割带（100% 笔直） |
| `AccelSwitch` | 加速开关·不掉画质 | Kitchen INT8 + TE 预测 + Qwen KV Cache 三合一，一档切换 |

## 安装

**本机已装**（`ComfyUI/custom_nodes/ComfyUI-ChineseImageSuite/`）：ComfyUI 菜单点「重新加载自定义节点」即可，无需重启。

**给别人装**：把整个文件夹复制到对方 `ComfyUI/custom_nodes/` 下，重新加载自定义节点。无 pip 依赖，无模型下载。

## 配套工作流（三个 JSON）

### 1. 纯文生图生成器_Qwen21_高清清晰.json —— 文字进、单张图出（零图片节点）

链上**没有任何图片输入节点**：纯文字描述 → 直接出图。人物、场景、广告都从这出。

用法（界面只碰「纯文生图面板」一个节点）：
- `提示词`：写画面描述。留空也行——选下面的预设自动拼
- `人物预设`：空 / 女性全身锁（性别+族裔+身形+细腿+C 罩杯偏饱满全套）/ 男性（净面无须+匀称）
- `场景预设`：空 + 16 张现成 BG 设定（P17-P32：老作坊堂屋三种时段/车间两种/仓库两种/医院病房/集市口/桂兰小馆/街道河堤/会展中心/竞标会议室/合作社豆田/厂区小路/隔间卧房），每张带时段/天气/光向/陈设逐件落点/天气后果，选了就出
- `分辨率档位`：默认 **16:9 高清 1920×1088（2MP，直出清晰档）**；可选 2K（2752×1536 等，更慢有 OOM 风险）、标清 1376×768（快）、9:16 竖屏三档、1:1 两档、自定义宽高（16 的倍数）
- `速度档位`：**均衡 25 步（默认，viggle 自动关，保画质）/ 质量 40 步 / 精细 50 步 / 快速 6 步（草稿用，viggle 开）/ 自定义步数**

**加速一键切**：速度档同时驱动两样——KSampler 步数自动跟着变、viggle LoRA 强度自动 0/1（均衡/质量/精细=关，快速=开）。不用手动 bypass 任何节点。模型链上另有「加速开关」节点（见下节），画质优先档可一键全关回退。

**清晰度说明**：Qwen-Image 2.1 是原生 2K 模型，不放大直接出就是原生清晰度。四要素：分辨率给足 + 步数 40-50 + bf16 满血 VAE + 质量档（viggle 会略软）。2060 12G 实测：1MP 约 200 秒、2MP 约 230-280 秒。想要更大尺寸直接调分辨率档，不需要二段式放大。

### 2. 人物多视图生成器_Qwen21_中文生图套件.json

一条链通吃两种模式，靠 TextEncodeQwenImageEditPlus 自适应：

- **纯文字直出**（默认态）：`LoadImage` 与 `viggle LoRA` 两个节点处于 bypass（置灰）状态，直接改「多视图提示词组装」里的 `人物提示词` + 选 `视图模式`（三视图/四视图/五视图/纯文字背景图/广告文字海报/自定义），点运行。
- **参考图锁脸**：取消 `LoadImage` 的 bypass，选一张人物图——模型按参考编辑模板编码，脸被锚定，出图仍是多视图格布局。

控件说明：
- `视图模式`：六选一。格布局句用**比例写法**（"横向均分为三个等宽格"），手改分辨率不会错位。
- `格数` 自动接 `多视图分割线` 节点——提示词说分几格，成图就画几条线，不用手动对齐。
- `EmptyLatentImage` 宽高**开放手改**。默认 1376×768（16:9）。常用档位：

| 档位 | 宽×高 |
|---|---|
| 16:9 标清 | 1376×768 |
| 9:16 竖屏 | 768×1376 |
| 1:1 方图 | 1024×1024 |
| 16:9 2K | 2752×1536 |
| 9:16 2K | 1536×2752 |

- 宽高须为 16 的倍数（模型 latent 要求）。

**加速三档**（靠「加速开关」节点切换，不靠 bypass；步数永远可手改，不锁）：
| 档 | 开关设置 | 单张耗时（2060 12G，1376×768） |
|---|---|---|
| 画质优先 | 加速档位=画质优先（零预测，画质基准） | ~150-190 秒 |
| 均衡（默认） | Kitchen INT8 + TE 1 连预，阈值 0.06 | ~80-110 秒 |
| 速度 | Kitchen INT8 + TE 2 连预，阈值 0.06 | ~60-90 秒 |

viggle 6 步为官方 sigma 口径，cfg 保持 1.0、不写负向。

### 3. 三视图换装_Qwen21_不换脸零遮罩.json

零遮罩全自动：参考图 + 脸锁提示词，只换衣服不换脸。

- `输入类型` 选「单张人物图」或「三视图」——选三视图会自动追加分格位置保持句。
- `服装描述` 写新服装（款式/材质/颜色）。
- KSampler 的 `denoise` 按节点输出的「建议denoise」填：单图 0.70 / 三视图 0.65。低了衣服换不掉，高了脸会漂，这是唯一风险旋钮。
- 链上预挂两个 LoRA：换身（`bfs_body_swap`）+ 身份保持（`identity_edit`），双保险；加速档 viggle 默认 bypass。

## 加速开关（AccelSwitch）—— 不掉画质的加速

三层加速打成一个节点，**模型进、模型出**，接在「所有 LoRA 之后、KSampler 之前」（顺序不能反，LoRA 放在加速前面，否则加速失效、画面随机崩坏——这是社区高频坑）。

| 层 | 内容 | 说明 |
|---|---|---|
| 1 | Comfy Kitchen INT8 注意力 | 不压步数，优化每步内部运算；官方口径整体 2-2.5 倍、画质损失低、边缘保持优于 SageAttention；Turing（20 系）实测可用 |
| 2 | TE Predictor 输出预测 | 保持原采样步数，预测后续步输出跳过实算；复用阈值 0.06 为原厂测试最佳 |
| 3 | Qwen 2.1 官方 Prefix KV Cache | 编辑流（参考图/换装）收益最明显；档位 auto+default 无损 / auto+int8 半存 / cpu+int8 省显存 / off 关闭 |

三档中文档位：

- **画质优先**：零预测加速（画质基准，出问题一键回退这档）
- **均衡（默认）**：Kitchen INT8 + TE 标准预测（1 连预）+ KV 无损
- **速度**：Kitchen INT8 + TE 激进预测（2 连预，画质偏差风险升高）+ KV int8

控件：`加速档位` / `复用阈值`（0.06 默认，调大更快、偏差风险升高）/ `KV缓存档位` / `详细日志`（控制台打印 TE 预测逐步决策）。

第二路输出「状态」实时报告本档实际启用了什么（例如 TE 模块缺失时自动降级为仅 KV，状态文本会明说）。

依赖说明：TE 预测层按路径动态加载 TE-Speed 编译节点（`nodes.pyd`），找不到时自动降级，不影响 Kitchen/KV 两层。低配卡（12G）不要把三层全开最高档，防爆显存；一切以实测对比为准， Kitchen 官方标记为实验特性。

## 多视图脸型一致性（重要）

纯文生图多视图**不保证**各格同一人（官方 FAQ：每轮采样新噪声，格间无锚定）。三条路：

1. **直出 + 固定 seed + 挂四视图/一致性 LoRA**：像，不完全同。适合对脸一致性要求不高的场景。
2. **删格布局句出一张单人正面图，接进参考槽**：多视图提示词 = 人物描述 + 格布局句，删掉格布局句（"画面分三格…"那段）换成"正面全身像"就是单人图提示词；出图满意后接参考图，配完整多视图提示词走编辑流——**脸锁死**。
3. **手上任何现成人物图接参考槽**：零额外功夫，脸锁死。

清晰度与脸一致性无关：分辨率给足（默认 1MP 起步，2K 可用）+ VAE 为 bf16 满血 + 步数 40 上下即官方画质口径；viggle 6 步官方实测与 40 步"多数提示词看不出区别"。

## 扩展（给别人改）

提示词数据与逻辑分离，改数据文件即可，不用动 nodes.py：

- `presets.py`：加场景 → 在 `SCENE_PRESETS` 加一行 `(标签, 场景句)`；改人物锁 → 改 `CHARACTER_PRESETS`；加分辨率/速度档位 → 改 `RESOLUTION_PRESETS` / `SPEED_PRESETS`。
- `view_layouts.py`：加视图模式 → 在 `VIEW_MODES` 加一行 `(格布局句, 格数)`；改画质句 → 改 `QUALITY_SENTENCE`。
- `swap_prompts.py`：改锁脸严密度 → 改 `FACE_LOCK`；加换装类型 → 在 `DENOISE_SUGGEST` 加一行。

提示词纪律（实证口径，改数据时请保持）：描述成品画面不描述请求；格数用比例句不写像素；除人物外纯净浅灰底；不用否定句；同一对象提及不超过两次。

## 已知限制

- 多视图直出的脸一致性见上节，不保证。
- 侧面角度偶尔与提示词相反（换 seed 重跑，官方 Character Sheet 工作流同样存在）。
- 换装 denoise 是概率性平衡，极端服装改动可能需 0.75-0.8，但脸漂风险随之上升。
